# What is enforced, and how far

**Levels**
- **Hard**: a hook or permission rule stops the action, and the user's prompt answer is the approval.
- **Partial**: some forms are caught; others get past the hook.
- **Advisory**: only the rule text applies.

**Evidence columns**
- *Unit*: `tests/test_hooks.py`.
- *Live*: `tests/live/run.sh`, real Claude Code 2.1.309, headless, run 2026-10-23.

**Permission modes:** in Manual, Accept edits, Plan and Auto, a tier-2 call opens a permission prompt, and the user's answer is the approval. In Bypass permissions and Don't ask, a hook's "ask" would be approved silently or denied without asking [Likely, per the docs], so the hook denies instead and tells the agent to explain. The ask rules are written for both the Bash and the PowerShell tool.

**Live on Windows (2026-10-24):**
- the rules loaded;
- `git reset --hard` through the PowerShell tool opened the prompt (the user accepted it by mistake, so the call ran);
- the Stop hook enforced the report.

**Live on Windows (2026-10-25/26):** a turn that asked with AskUserQuestion and listed 2 Waiting on you items passed; a turn that listed 1 item without asking was blocked with the 2.2 reason. The Q89A–Q91A additions are unit-tested only. Q94A, live (2026-10-26): a message to another local session went through with no tier-2 log entry.

The same run exposed over-asking: the desktop app's own `mcp__ccd_turn__update_plan` triggered prompts. Fixed: local app servers (ccd_turn, ccd_session, ide, claude_preview) and plan/todo/status tools no longer ask. Neither does `mcp__ccd_session_mgmt__send_message`, a message to the user's own Claude session (Q94A); that server's other tools, such as deleting or archiving a session, still ask.

**Raw API adapter** (`adapters/api/playbook_api.py`): the same policy runs before every tool call, the same report check after a changing turn, and the headless form of the 2.2 check after every turn (one retry for both). So the rows above for 2.3, 5.1, 1.3 and 2.2 (headless) apply there too. One difference: an "ask" goes to the adapter's own prompt in the terminal, and in `tools/compare.py` every "ask" is refused. Tested offline only (`tests/test_m4.py`).

**Hook errors:** any internal error on PreToolUse answers "ask" (a permission prompt) instead of crashing, so a bug neither lets a tier-2 action through silently nor locks every tool.

**Known holes**, from the docs and not tested here:
- A mod on a personal account can approve past ask and deny rules.
- Repo hooks do not run in claude.ai cloud project threads.
- `onFailure: "block"` needs Claude Code 2.1.295 or later. It has no effect on Stop.
- Whether a permission prompt can be answered from the phone app was not tested.

**Live-run observation:** child `claude -p` runs started from inside a Claude Code session reported the parent's `session_id`, so they shared hook state. This is harmless for normal use, where every session has its own id.
